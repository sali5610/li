## 1. End state, boundaries, ownership

**Definition of the finished Design System:** a single source of visual values; typed, semantic, reusable component API with consistent behavior and responsive rules; an **Atomic Design** inventory (Foundations → Atoms → Molecules → Organisms → Templates → actual Pages); a **UI-only ontology** linking tokens, components, states, slots, patterns, screens, rules and QA evidence; real rendering/interaction/accessibility regression; a visual component gallery; and a controlled per-screen React migration path. Successful code tests, physical-device QA, human G2 and release authorization are **separate statuses**.

**Inside this plan:** all first-party Design Library tokens/styles/icons/controls; meaningful interactive states; VI/EN; iPhone/iPad portrait/landscape/Split View/keyboard/short-height/resizing; Home scene layout, guide grid and common app navigation; UI treatment for login/logout/sync/mentor (NOT server logic); React UI shared primitives and staged L09 adoption; audits, CI, docs and cleanup.

**Outside this plan:** Knowledge/course ontology ONT-03, method-fit and academic content, search ranking/graph traversal/mentor intelligence ONT-04, embeddings/vector ONT-05, curriculum authoring, Google invite database/RLS/security implementation, private state migrations, paid services, and Cloudflare automatic release. Existing [ONT-01 typed registry](https://app.notion.com/p/41d6cf6db72a81188986ed5f65d17a5e) [PR #127](https://github.com/sali5610/li/pull/127) is a **DONE spec/validator dependency, still draft/unmerged**; [ONT-02 UI/React crosswalk](https://app.notion.com/p/41d6cf6db72a81e0aa1ef66c7ddc0507) remains **P0 Backlog** until implemented.

**Visual non-negotiables:** approved li. paper/porcelain/moss/sand roles; Crimson Text editorial roles + suitable body sans; square ordinary controls and hard offset shadow; sand selected-nav **oval**, filter chip **pill**, Lão Lý speech-bubble shape; approved *Trong gương only* art identity; full-size iPad text/density baseline; approved single iPad landscape Home illustration cropped for portrait; Lưu before Đào sâu; and **Thần Chú compact method cards exactly 2 columns at widths 320–640 CSS px**. Do not impose Material visual skin, invent a new brand, auto-convert old source IDs or erase approved exceptions. G2 visual signoff overall remains OPEN.

## 3. Concrete iPhone/iPad responsive contract (not just media queries)

| Effective app window size (CSS px) | Product layout baseline | Mandatory behavioral rule |
| --- | --- | --- |
| **Compact 320–599** | Single reading column; compact safe-area navigation, flexible actions; **Guide/Thần Chú 2-up exception continues through 640**. | Readable 16/24 body baseline and ≥14/20 essential supporting labels; intended new 48 CSS px touch targets; wrap/stack without hiding actions. |
| **Medium 600–839** | Responsive 1–2 columns by **container** capacity; iPad Split View may be compact. | Do not infer whole tablet scale from iPad user agent. Keep 601–743 header icon targets at intended 48px. |
| **Expanded 840–1199** | Two pane only when main reading area and controls fit; avoid wide long paragraphs. | Larger control/icon/type scale only in appropriate full-size tablet density context, not every wide iPhone. |
| **Wide ≥1200** | Reading max-width, optional contextual secondary pane. | Short-height landscape/keyboard can still trigger compact vertical behavior. |

These are **li. proposed width classes**, not fixed Apple or Material values. Container cutovers should be based on actual content and tested rather than arbitrary device names. Full-size iPad existing baseline: portrait body **18/28**, gutter **32**, card pad **28**, control min **56**, icon **24**; landscape body **18/28**, gutter **40**, card pad **32**, control min **56**, icon **24**. Keep approved values as initial parity; any visual change is a separate G2 discussion.

**Required test matrix (CSS viewport sizes)**: iPhone 320×568, 375×667, 390×844, 402×874, 430×932; phone landscape 568×320, 667×375, 844×390; split 600/640/744 widths; iPad portrait 744×1133, 820×1180, 970×1408, 1024×1366; iPad landscape 1133×744, 1194×834, 1366×1024, 1408×970; desktop 1440×900; continuous width sweep 320→1440, 200% text and relevant 400% reflow.

**Home iPad special acceptance**: portrait uses a crop of the **single approved iPad landscape artwork**. Question remains inside mirror; one shared centered bubble above the two aligned actions (Lưu → Đào sâu). Rotate **portrait→landscape→portrait→landscape** without refreshing, blank paper strip, wrong browser-chrome height, lost question, inaccessible buttons or body scroll in *ordinary supported conditions*. When keyboard, 200% text or short viewport makes controls unreachable, an accessibility escape/reflow mechanism is required as a **G2-reviewed composition exception**, never a hidden CTA.

**Interaction/a11y**: never lock pinch zoom, ensure accessible name/role/value/focus, keyboard order/restore, safe-area inset and virtual-keyboard handling; minimum touch areas by actual component contract, not icon graphic size. Meaningful states include **loading, empty, error, offline, retry, disabled, saving, saved only after confirmed persistence, denied**. Safari CSS tap highlight must not hide focus-visible.

## 4. ONT-02 Design System ontology — one shared typed contract

**Ontology scope is ONLY UI**: consume the existing [ONT-01 draft spec/schema](https://github.com/sali5610/li/pull/127) once reviewed/pinned, then implement [ONT-02 UI rule crosswalk](https://app.notion.com/p/41d6cf6db72a81e0aa1ef66c7ddc0507). Do NOT make a second token source, ontology backend, learning graph or new navigation tier.

- **Node vocabulary in scope:** UI DesignToken, Component, Variant, State, Slot, Pattern, Screen, Flow, Action, UIRule, QAGate and Decision **as supported by the version-pinned ONT-01 registry**; no new kinds before a separate schema review.
- **Typed path:** Component **USES_TOKEN** token; Pattern **HAS_SLOT** slot; Component **FILLS_SLOT** slot; Screen **USES_PATTERN** pattern; UIRule **CONSTRAINS** slot/pattern; QAGate **VALIDATES** rule. Use only allowed ONT-01 endpoint types; do not infer that a sample edge is actually implemented.
- **Required metadata:** stable canonical IDs, token role/variant/state, platform scope (width/container/height rather than device-name only), source file/selector/React prop, version, decision approval and replacement status, owner, fixture/test URL+SHA. Source and approval status must be independent.
- **Pilot trace:** Button → semantic action token → ActionGroup primary slot → L09 *UI Screen* → action-hierarchy rule → specific browser/accessibility test; cover compact phone, iPad portrait/landscape/Split View, disabled/loading/VI-EN. Graph validator detects illegal edges; **real rendered tests** prove actual pixels and interaction.
- **Negative tests:** unknown token, orphaned slot, unsupported variant, missing UI rule gate, false approved status, duplicate selector ownership, stale responsive variant. The ontology may explain why a component is used, but cannot certify iPad Safari or G2 by itself.

**Explicitly out of scope:** ONT-03 academic/L2×L3 graph, ONT-04 Search/Lão Lý knowledge reasoning, ONT-05 vector retrieval, learner evidence/Neon schema/auth permission logic. Their independent backlog state is unchanged.

## 5. Per-component contract / Definition of Done (mandatory for every active family)

For each component, its contract must include: **(1)** canonical ID and Atomic level; **(2)** purpose/when-to-use/when-not-to-use; **(3)** anatomy/slots; **(4)** sizes/variants/responsive density; **(5)** states/transitions and error recovery; **(6)** reference→semantic→component token mapping; **(7)** Do/Don't and approved exceptions; **(8)** typed React props/controlled behavior/ARIA/focus; **(9)** VI/EN long-copy and responsive behavior including safe-area/short-height; **(10)** interactive gallery and accessibility/visual/browser evidence with commit SHA and **PASS/FAIL/UNVERIFIED**; **(11)** G2 approval state. Do not mark an empty spec “Ready”.

**Example**: Button primary SHOULD use the action semantic tokens, preserve square normal geometry, a visible focus ring, accessible action label and target size. It MUST NOT become unapproved 6px rounded because the React pilot CSS defines that radius; must not say “saved” before actual confirmation. ActionGroup wraps only as its content demands and preserves logical action order.
