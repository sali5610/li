## 3. Architectural decision consequences — bounded

**New evidence:** React 19 + TS + Vite can render and persist the real L09 challenge + self-review workflow using authentic lesson copy while following li. runtime tokens. This makes an incremental island *technically plausible*, not costless to integrate.

**Still not demonstrated:**
- Attaching React to the actual `#page-lessonL09` route while leaving legacy bookmark, Tủ Riêng recents, global locale and Lão Lý interactions intact; no duplicated screen owner.
- Complete L09 guided example, source attribution panel, existing side sheet, native browser focus handling, media and CTA states; page is only the two interactive surfaces.
- Real app's `window.liLanguage` global events and adapter to `li.review.L09-1-2.v1` without changing or corrupting saved answers.
- Existing all-screen CSS, exact visual/pixel layout, iPad landscape rotation/resume and iPhone Safari/PWA; 390/820 desktop Chrome width is not physical QA.
- Web Vitals, JS parsed cost, network size across HTTP caching, offline behavior, screen-reader VoiceOver, build reproducibility lockfile and full source migration estimate.
- More maintainable code over months: no longitudinal engineering data or randomized comparison of developer productivity exists.

**Practical migration inventory for a future selected React island** (code-owner-specific, not approved work):

**Recommendation to G3:** keep a modular Vanilla shell on current production and treat React+TS+Vite as a **bounded future migration candidate** only; a *production-integrated* island with full original L09 UI, identical state key and native publisher boundaries would require explicit implementation + privacy/security/rollback gates **after** the PO chooses frontend strategy. Lit remains a valid smaller option according to [PR #109](https://github.com/sali5610/li/pull/109); this test does not eliminate it.
